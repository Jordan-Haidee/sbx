# TD7 Design

## Goal

在现有 `sbx` 库中新增一个高质量的 `TD7` 算法实现，基于当前 `TD3`/离策略 JAX 基础设施，完整包含 TD7 论文中的核心新增组件与 checkpoint policy 训练/评估流程，并保持与其他 `sbx` 算法相似的调用接口。

## Scope

本次实现覆盖：

- 独立的 `TD7` 算法目录与导出接口
- `SALE` 表示学习模块
- `fixed embeddings` / `fixed target embeddings`
- value clipping
- `LAP` 优先级回放
- checkpoint policy 训练/评估流程
- 基于 `jax.jit` 的训练更新路径
- 与第三方 JAX 参考实现对齐的主要超参数
- 单元/集成 smoke tests

本次实现不覆盖：

- `simba` / `simbav2` 网络架构
- offline RL 的 TD3+BC 项
- 与论文无关的通用离策略训练框架重构

## Sources And Alignment

实现以三类参考为准：

1. 论文 `resources/impl_td7/td7_paper.pdf` 与其文本版 `resources/impl_td7/td7_paper_text.md`
2. 作者 PyTorch 代码 `resources/impl_td7/td7_origin_code`
3. 第三方 JAX 参考实现 `resources/impl_td7/jax-baseline-code`

对齐原则：

- 算法行为优先对齐论文与作者代码，尤其是 checkpoint lifecycle、fixed encoder 语义、value clipping、target update 节奏
- 默认超参数尽量对齐第三方 JAX 实现
- `sbx` 内部接口与工程风格优先对齐现有 `TD3`、`SAC`、`TQC`

## High-Level Architecture

新增一个独立算法目录 `sbx/td7`，而不是在 `TD3` 上叠加模式开关。

原因：

- TD7 的 rollout/training lifecycle 与标准 `TD3` 存在结构性差异
- checkpoint policy 会影响训练、评估和 `predict()` 路径
- `SALE`、LAP 与 value clipping 都引入额外状态，不适合污染 `TD3` 主路径

新增模块：

- `sbx/td7/td7.py`
  - 算法主类 `TD7`
  - 自定义 `learn()` / rollout loop
  - checkpoint lifecycle
  - delayed training pulses
  - logging / save-load 对接
- `sbx/td7/policies.py`
  - `TD7Policy`
  - encoder / actor / critic Flax modules
  - train states 初始化
- `sbx/td7/replay_buffer.py`
  - `TD7ReplayBuffer`
  - LAP 采样与 priority 更新
- `sbx/td7/__init__.py`
  - 导出 `TD7`
- `tests/test_run.py`
  - `TD7` smoke / save-load / predict 路径
- `tests/test_buffers.py`
  - `TD7ReplayBuffer` 基础行为
- `sbx/__init__.py`
  - 增加 `TD7` 导出

## Public API

目标调用方式与现有算法保持一致：

```python
from sbx import TD7

model = TD7("MlpPolicy", "Pendulum-v1")
model.learn(10_000)
```

策略别名保持与 `TD3` 一致：

- `MlpPolicy`
- `MultiInputPolicy`

`simba` 相关 policy 不在本次范围内。

## Network Design

### SALE Encoder

按论文与作者代码实现两个编码路径：

- `zs = f(s)`
- `zsa = g(zs, a)`

其中：

- `f(s)` 为 `state -> ELU MLP -> AvgL1Norm -> zs`
- `g(zs, a)` 为 `concat(zs, a) -> ELU MLP -> zsa`

默认维度：

- `zs_dim = 256`
- encoder hidden dim = `256`

### Actor

Actor 输入为 `(s, zs)`，而不是单独 `s`。

实现形式：

1. 对 `s` 先过一层线性层
2. 对该线性层输出施加 `AvgL1Norm`
3. 与 `zs` 拼接
4. 经 `ReLU` MLP 输出 `tanh(action)`

这对应论文中的：

- `pi(zs, AvgL1Norm(Linear(s)))`

### Critic

Critic 为 twin critic，输入为 `(s, a, zs, zsa)`。

每个 critic 结构：

1. `(s, a)` 先拼接
2. 过一层线性层
3. 对该输出施加 `AvgL1Norm`
4. 与 `(zs, zsa)` 拼接
5. 经 `ELU` MLP 输出标量 Q 值

这对应论文中的：

- `Q(zsa, zs, AvgL1Norm(Linear(s, a)))`

## Training State Design

`TD7Policy` 需要维护以下状态：

- `actor_state`
- `actor_target_state`
- `critic_state`
- `critic_target_state`
- `encoder_state`
- `fixed_encoder_state`
- `fixed_encoder_target_state`
- `checkpoint_actor_params`
- `checkpoint_encoder_params`

在 `sbx` 现有 `RLTrainState` 基础上，主训练状态仍优先使用：

- `params`
- `target_params`

但 TD7 有三个不同角色的 encoder：

- `encoder`: 当前在线训练 encoder
- `fixed_encoder`: 当前 actor/critic 使用的冻结 encoder
- `fixed_encoder_target`: target Q 使用的冻结 target encoder

因此 `TD7` 算法类本身会持有这些额外状态，而不是强行塞进一个单一 train state。

## Core Losses

### Encoder Loss

按论文公式：

```text
L_encoder = MSE(g(f(s), a), stop_gradient(f(s_next)))
```

性质：

- 仅训练 encoder
- 不让 actor/critic 的梯度回传进 encoder

### Critic Loss

按 TD7 语义：

1. 用 `fixed_encoder_target` 编码 `s_next`
2. 用 `actor_target` 产生带噪声的 `a_next`
3. 用 `fixed_encoder_target` 计算 `zsa_next`
4. 用 `critic_target` 得到双 Q target
5. 先对 target Q 做 value clipping
6. 形成 Bellman target

critic 的当前输入则来自：

- `fixed_encoder(s)`
- `fixed_encoder.zsa(zs, a)`

损失函数采用 Huber 风格，与作者实现及第三方 JAX 对齐。

### Actor Loss

按当前 actor 产生动作：

- `a_pi = actor(s, fixed_zs)`
- `fixed_zsa_pi = fixed_encoder.zsa(fixed_zs, a_pi)`
- `Q_pi = critic(s, a_pi, fixed_zsa_pi, fixed_zs)`

actor loss 为：

```text
L_actor = -mean(min(Q1_pi, Q2_pi))
```

本次不实现 offline RL 的 BC 项。

## Fixed Embeddings And Target Update

TD7 的关键不是 EMA soft update，而是周期性硬更新。

每 `target_update_interval = 250` 次训练更新时执行：

- `actor_target <- actor`
- `critic_target <- critic`
- `fixed_encoder_target <- fixed_encoder`
- `fixed_encoder <- encoder`

含义：

- actor/critic 在一个更新区间内始终消费固定 embedding
- target Q 在该区间内消费更旧一层的 fixed target embedding

这与标准 `TD3` 的 soft target update 不同，必须独立实现。

## Value Clipping

为缓解 SALE 带来的 extrapolation error，TD7 需要维护 target value 的范围。

状态：

- `running_min_value`
- `running_max_value`
- `target_min_value`
- `target_max_value`

流程：

1. 当前训练步根据 Bellman target 更新 `running_min_value` / `running_max_value`
2. 生成下一步 target Q 时，将 target critic 输出裁剪到 `target_min_value` / `target_max_value`
3. 每次执行 target/fixed encoder 硬更新时：
   - `target_min_value <- running_min_value`
   - `target_max_value <- running_max_value`

这是算法层面的动态状态，不属于 policy 本身。

## LAP Replay Buffer

新增 `TD7ReplayBuffer` 支持：

- 新 transition 插入时使用当前 `max_priority`
- 采样时返回 `indexes`
- 训练后按 `indexes` 回写 priority
- 硬更新后重置/重算 `max_priority`

priority 定义：

- 基础 priority 为 `max(abs(td_error_q1), abs(td_error_q2), min_priority)`

实现策略：

- 对外暴露 `prioritized_replay_alpha`
- 采样分布由 buffer 内部用 `priority ** alpha` 构建

这与第三方 JAX 实现更一致，也便于测试和维护。

## Checkpoint Policy Lifecycle

这是 TD7 与现有 `sbx` 训练循环差异最大的部分。

### Action Selection

- 训练采样：
  - 使用 `actor + fixed_encoder`
  - 添加 exploration noise
- 评估 / `predict(deterministic=True)`：
  - 优先使用 `checkpoint_actor + checkpoint_encoder`
  - 若 checkpoint 尚未建立，则退回当前 `actor + fixed_encoder`

### Episode Accumulation

在 rollout 中按 episode 维护：

- `episodes_since_update`
- `timesteps_since_update`
- `current_window_min_return`
- `best_checkpoint_min_return`
- `max_episodes_before_update`

### Warmup Phase

在 `steps_before_checkpointing` 之前：

- `max_episodes_before_update = 1`
- 每个 episode 结束就执行一次 delayed training pulse
- checkpoint snapshot 可以在这个阶段初始化

### Checkpointing Phase

当训练步数达到阈值后：

- `max_episodes_before_update = checkpoint_max_episodes`
- 默认 `20`

window 评估规则：

1. 每个 episode 结束后更新当前 window 的最小回报
2. 若 `current_window_min_return < best_checkpoint_min_return`
   - 提前终止当前 window
   - 立即执行 delayed training pulse
3. 若 window 已满且没有差于当前 best checkpoint
   - 刷新 checkpoint snapshot
   - `best_checkpoint_min_return = current_window_min_return`
   - 执行 delayed training pulse

### Delayed Training Pulse

训练不是按 step 立即触发，而是在 window 结束时统一触发。

脉冲训练次数等于自上次更新以来累计的环境步数：

```text
num_updates = timesteps_since_update
```

这要和作者代码保持语义一致。

### Reset Weight

达到 `steps_before_checkpointing` 时：

- `best_checkpoint_min_return *= reset_weight`
- 默认 `reset_weight = 0.9`

这是作者代码中的 checkpoint 进入期平滑逻辑。

## JIT Strategy

TD7 必须充分利用 `jax.jit`，但 delayed pulse 的更新次数是动态的，不能简单把每次 pulse 的长度设为静态编译参数，否则会频繁重编译。

设计如下：

- 保留单个训练 chunk 的 `_train_chunk()` 为 `jax.jit`
- chunk 内使用 `lax.fori_loop` 或 `lax.scan`
- Python 层将一次 pulse 拆成若干固定长度 chunk
- 最后一个不足 chunk 的部分使用 padding + mask 处理

这样可以同时满足：

- 核心更新在 JIT 图中执行
- 避免因 episode 长度变化造成编译抖动
- 保持实现可读性

## Save / Load Semantics

`TD7` 的保存必须覆盖：

- actor / critic / encoder 当前参数
- actor target / critic target 参数
- fixed encoder / fixed encoder target 参数
- checkpoint actor / checkpoint encoder 参数
- value clipping 状态
- checkpoint lifecycle 状态
- JAX rng key

load 后必须保证：

- `predict(deterministic=True)` 的行为稳定复现
- 继续训练时不会丢失 checkpoint / clipping 状态

## Error Handling And Constraints

约束：

- 仅支持连续动作空间
- 支持 `MultiInputPolicy` 的最小 dict flatten 方案，与 `TD3` 保持一致
- 不支持 `simba`
- 不支持 offline TD3+BC 分支

异常/保护：

- 若 action space 不是 `Box`，应直接断言失败
- 若 replay buffer 样本数不足，不进入 delayed training pulse
- 若 checkpoint 尚未建立，评估路径回退到当前策略
- 若 pulse 最后一块不足固定 chunk 长度，必须通过 mask 忽略填充样本的梯度贡献

- `learning_rate = 3e-4`
- `qf_learning_rate = None`，默认与 actor 相同
- `encoder_learning_rate = 3e-4`
- `buffer_size = 1_000_000`
- `batch_size = 256`
- `gamma = 0.995`
- `learning_starts = 5000`
- `policy_delay = 2`
- `target_update_interval = 250`
- `exploration_noise = 0.1`
- `target_policy_noise = 0.2`
- `target_noise_clip = 0.5`
- `zs_dim = 256`
- `hidden_dim = 256`
- `prioritized_replay_alpha = 0.6`
- `min_priority = 1.0`
- `steps_before_checkpointing = 750_000`
- `checkpoint_max_episodes = 20`

## Testing Strategy

至少覆盖以下验证：

1. `TD7` smoke test
   - `Pendulum-v1` 上可初始化并短时间 `learn()`
2. save/load test
   - 保存后重新加载，`predict(deterministic=True)` 输出一致
3. replay buffer test
   - 插入、采样、priority 更新、`reset_max_priority()` 行为正确
4. checkpoint lifecycle test
   - 用短 episode dummy env 验证 episode 累积、窗口比较和 delayed pulse 触发
5. key/state progression test
   - 训练后关键状态发生更新，避免 JAX key 卡死

## Implementation Risks

主要风险：

- 将 checkpoint lifecycle 接入现有 SB3 learn/rollout 体系时，容易破坏 callback/logger 节奏
- 动态 pulse 长度若设计不当，会引入频繁 JIT recompilation
- save/load 若遗漏 checkpoint 或 clipping 状态，会导致 reload 后行为漂移
- 自定义 replay buffer 若接口偏离现有 `sbx` 过大，会抬高集成复杂度

对应策略：

- `TD7` 单独实现 rollout loop，尽量只复用 `OffPolicyAlgorithmJax` 的基础设施
- 训练 pulse 使用固定 chunk 的 jitted inner loop
- 明确列出所有需持久化状态并补 save/load tests
- replay buffer 接口尽量贴近现有 sample/add 语义

## Acceptance Criteria

满足以下条件即可视为完成设计：

- `TD7` 在 `sbx` 中以独立算法存在
- 完整实现 `SALE + fixed embeddings + value clipping + LAP + checkpoint policy`
- checkpoint lifecycle 包含：
  - 按 episode 累积
  - window 最小回报比较
  - 提前终止 window
  - delayed training pulse
  - checkpoint snapshot 评估/预测路径
- 核心训练路径通过 `jax.jit` 加速
- 默认超参数与第三方 JAX 实现基本对齐
- `simba` 未被纳入实现范围
- 至少有 smoke/save-load/buffer/checkpoint 相关测试覆盖
